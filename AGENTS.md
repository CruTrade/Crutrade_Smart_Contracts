# AGENTS.md

Solidity smart contracts for the CruTrade marketplace (luxury goods wrapped as NFTs) on Avalanche,
plus a TypeScript package (`@crutrade/contracts`) that ships the ABIs, deployed addresses and
TypeChain types. Build system is Foundry for the contracts and Bun/tsup for the package.

Last verified against commit: 136615be21009eb2ea72a249527f07e2c1c61ab3

## Dev environment

For container onboarding, run `docker compose up --build -d --wait`; this builds the pinned
toolchain and starts Anvil with automatic local deployment. `docker compose run --rm test` runs
Foundry tests offline in a disposable container. See `README.md` for state, reset and port controls.
Docker inputs are allowlisted by `.dockerignore`; never add host secrets or dependency caches.
Container startup code lives in `docker/local-stack.mjs`. Changes to it require validating initial
deployment, restart reuse and failure handling on a disposable local volume. The Compose stack is
local-only; it does not configure or authorize remote deployments.

Requires Foundry (verified with forge 1.2.1), Bun (verified with 1.4.2) and Node (for `npx typechain`).

| Task | Command |
| --- | --- |
| Install Solidity deps | `forge soldeer install` (populates `dependencies/`) |
| Install JS deps | `bun install` |
| Compile | `forge build --via-ir` |
| Typecheck TypeScript | `npx tsc --noEmit` |
| Full package build | `npm run build` |
| Local chain | `npm run anvil` |
| Deploy local / mainnet | `npm run deploy:local` / `npm run deploy:mainnet` |

`npm run build` runs `forge build --via-ir`, then `tsup`, then regenerates `types/` and rewrites the
root `index.ts`. It overwrites checked-in files, so run it only when you intend to publish.

There is no linter. `forge fmt --check` currently fails on 30 of the 31 Solidity files in the repo, so
never run `forge fmt` without being asked: it would reformat the whole codebase.

## Testing

Foundry tests live in a single suite, `test/Crutrade.t.sol` (115 tests at the verified commit).

```bash
forge test                              # full suite
forge test --match-test test_ListingFlow -vv   # single test, preferred while iterating
forge test --match-contract CrutradeEcosystemTest
```

Prefer the `--match-test` form during development. Add `-vvv` for traces on a failure.

## Code style and conventions

- Solidity pragma is pinned to `0.8.30` in every file. Do not widen it to a range.
- Every production contract is a UUPS proxy: `constructor() { _disableInitializers(); }`, state set in
  `initialize(...)`, and `_authorizeUpgrade` gated by `onlyRole(UPGRADER)`.
- Business logic goes in `src/abstracts/<Name>Base.sol` with `internal` functions; `src/<Name>.sol`
  holds the thin external surface, modifiers and access control. Keep that split.
- Access control is never `msg.sender == owner`. Use the modifiers from `src/abstracts/ModifiersBase.sol`
  (`onlyRole`, `onlyDelegatedRole`, `onlyWhitelisted`, `checkAddressZero`), which delegate to the
  `Roles` contract. Role identifiers are `keccak256('NAME')` constants.
- Errors are custom errors declared next to the contract that reverts, never revert strings in new code.
- External state-changing entry points follow checks-effects-interactions and are `whenNotPaused`.
- Interfaces in `src/interfaces/` carry the shared structs; do not duplicate a struct in two files.
- ID counters start at 1 (`_nextSaleId`, `_nextWrapperId`, `_nextBrandId`) so 0 means "absent".
- TypeScript in `script/` targets Bun (`#!/usr/bin/env bun`), uses `viem` or `ethers` v6, reads
  addresses from `broadcast/` or `deployments/`, and exits non-zero on failure.

## Architecture summary

`Roles` is the hub: it stores role assignments, the "primary address" per role, delegation flags and
payment-token configuration. Every other contract holds an `IRoles` reference and resolves its peers
through `roles.getRoleAddress(<ROLE>)`. `Sales` orchestrates listing and buying, calls `Wrappers` for
NFT custody and `Payments` for fee settlement; `Payments` reads tiers from `Memberships`.

Depth: `docs/02-architecture.md`, `docs/04-core-flows.md`, `docs/11-api-reference.md`.
Full chapter list: `docs/README.md`.

## Boundaries

Never edit by hand:

- `index.ts` (generated by `script/update-package.ts`; header says so)
- `types/**` (generated by TypeChain via `script/generate-types.ts`)
- `out/`, `cache/`, `broadcast/`, `dist/`, `deployments/` (build and deploy artifacts)
- `dependencies/`, `node_modules/`, `soldeer.lock`, `bun.lock` (vendored / lockfiles)

Also off limits: `.env` (real keys, gitignored), any deployed proxy address constant in
`script/*.s.sol` and `script/*.ts`, and the storage layout of any already-deployed contract.

## Gotchas

- **No storage gaps.** None of the abstract bases declare `__gap`. Adding a state variable to
  `ModifiersBase`, `ScheduleBase` or any `*Base` shifts every slot of the deriving contract and
  corrupts live proxies. Append new variables to the most-derived contract instead.
- `via_ir = true` lives in `[profile.default]` of `foundry.toml`, so every build gets it, including the
  plain `forge build --skip test` in the upgrade wrappers. Only a non-default `FOUNDRY_PROFILE` could
  turn it off, which would change the bytecode.
- `ffi = true` is enabled in `foundry.toml`. Foundry scripts here can execute shell commands.
- Fiat payments are signalled by passing `erc20 == address(0)`; `Payments` then pulls funds from the
  address holding the `FIAT` role and uses the default fiat token from `Roles`.
- `Sales` custodies the wrapper NFT between `list` and `buy`/`withdraw`. A withdraw deletes the sale
  record; a buy only flips `active` to false.
- `npm run deploy:testnet` passes the literal `fuji`, which `script/deploy.ts` rejects as an unknown
  network. Use `forge script script/deploy.s.sol` with `NETWORK=fuji` instead.
- Known defects are inventoried in `docs/19-tech-debt.md`. Read it before touching `Payments.initialize`
  or `ScheduleBase.__ScheduleBase_init`.

## Change protocol

Every code change in this repo must:

1. **Update `CHANGELOG.md`** in the same change, under `## [Unreleased]`, using Keep a Changelog
   sections (Added / Changed / Fixed / Removed / Security). One line per change, user-facing wording,
   naming the touched module. No changelog entry means the change is not done.
2. **Use Conventional Commits**: `type(scope): short imperative summary`, max ~72 characters, e.g.
   `fix(sales): reject listings with an expired signature`. Body only when it adds information about
   what changed and why, not how. One logical change per commit; never mix a refactor with a feature.
   Commit after each discrete step, not only at the end.
3. **Update the docs in the same change** when setup, commands, architecture, conventions, config or
   the contract ABI surface change: the relevant `docs/` chapter plus `AGENTS.md` or the matching
   `.claude/rules/` file.
4. **Run `forge test` and `npx tsc --noEmit` before committing.** If a change touches the contract
   surface, also run `forge build --via-ir`.
